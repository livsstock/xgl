## 二、模型参数迭代卡（v1 → v2.5 调整清单）

### 2.1 M_sse 双因子加权 → 升级为四因子（高优先级）

**问题**：WB M_sse=42.1 给出"中性偏看空"，但实际大盘 up+0.97%。M_sse 对"指数横盘但板块轮动"环境不敏感。

**根因**：9/18 收盘 15 日涨幅 -1.02% + MA20 偏离 -0.27% → M_raw=-0.158 → M_score=42.1。两个因子都是负数，但今天半导体+4% / 房地产走强 / 中证500+1.94% 远超大盘——M_sse 完全没捕捉到。

**修复方案（M_sse v2.5）**：

| 因子 | 原权重 | 新权重 | 数据源 |
|---|---|---|---|
| 15日涨幅 | 60% | 30% | stock_data.chg_15d_pct |
| MA20 偏离 | 40% | 20% | stock_data.ma20_dev_pct |
| **板块宽度（新增）** | - | **30%** | daily_quote.上涨家数 / 总家数 |
| **Kuramoto R_value（可选）** | - | **20%** | 大海 v1.1-kuramoto 共享 |
| 合计 | 100% | 100% | - |

**验证窗口**：9/22-9/26（5 天），对比 v1 vs v2.5 在双 0 轴附近 +0.5%~1% 区间的方向胜率。若 v2.5 胜率 >70%，9/29 起切换默认版本。

**反馈路径**：`predictions/YYYY-MM-DD.json` 的 `_market_environment.M_sse_version` 字段由 "v1" → "v2.5"，reconcile.py 记录每个版本命中率。

### 2.2 量比阈值 1.3 → 动态化（中优先级）

**问题**：今日 4 只"放量"票里，五粮液量比 1.32 触发但 15:35 仅涨 +0.09%（假信号），半导体 ETF 量比 0.86 误判为不触发但涨 +0.58%。

**根因**：1.3 是固定阈值，在低波动日（今日上证振幅仅 ~1%）容易误判。

**修复方案（量比 v2）**：
```python
# 原版：固定 1.3 阈值
if vol_ratio >= 1.3: signals.append("放量")

# v2：动态阈值 = max(1.3, 当日大盘振幅 × 5)
threshold = max(1.3, mkt_amplitude * 5)
if vol_ratio >= threshold: signals.append("放量")
```
今日大盘振幅约 1.0%，动态阈值 1.3（不触发），五粮液 1.32 会降级为"接近触发"而非"已触发"。

**验证窗口**：9/22 起观察连续 5 天，"假信号"率从 25% 降到 10% 以下则采纳。

### 2.3 RSI6 超卖阈值 30 → 环境自适应（低优先级）

**问题**：紫金 RSI6=33.7 触发"接近超卖"（30-35 区间），15:35 实际 +0.29% 弱反弹，超卖信号成立但反弹力度弱。

**根因**：阈值 30 是 Wilder 经典值，但与"市场环境强度"无关——弱市 RSI30 已是底，强市 RSI40 才是底。

**修复方案（RSI v2）**：
```python
# 强市（M_sse≥60）：超卖阈值 35-40
# 中市（M_sse 40-60）：超卖阈值 30-35（保持原值）
# 弱市（M_sse<40）：超卖阈值 25-30
if m_sse >= 60: oversold_threshold = 35
elif m_sse >= 40: oversold_threshold = 30
else: oversold_threshold = 25
```
今日 M_sse=42.1 中市，紫金 33.7 仍属"接近超卖"（30-35 区间）合理。

**验证窗口**：5 天样本，9/26 评估。

## 三、反馈路径设计（自动化）

### 3.1 每日 16:10 触发链路

```
[15:00 收盘] daily_collect.py 抓 EOD 数据
       ↓
[16:10 触发] reconcile.py 跑三层对账
       ↓
[16:15] validate_feedback.py 自动生成"模型迭代卡"
       ↓
[16:20] 写 predictions/feedback-YYYY-MM-DD.json + reconcile/feedback-YYYY-MM-DD.md
       ↓
[9/26 周六上午] 阿牛哥 + 大海 一起审本周 5 张迭代卡，定版本切换
```

### 3.2 迭代卡字段规范

| 字段 | 类型 | 说明 |
|---|---|---|
| `version_from` | str | 当前模型版本（如 M_sse v1） |
| `version_to` | str | 建议版本（如 M_sse v2.5） |
| `change_summary` | str | 一句话变更原因 |
| `evidence` | list | 验证证据（"9/21 大盘 WB错实际 up"） |
| `parameter_deltas` | dict | 参数变化（如 15日权重 60%→30%） |
| `expected_improvement` | str | 预期效果（"方向胜率从 X% 提到 Y%"） |
| `validation_window` | str | 验证起止日期 |
| `rollback_criteria` | str | 回滚条件（"5 天后胜率<60% 即回滚"） |
| `approval_status` | str | pending / approved / rolled_back |

### 3.3 周六 9/26 决策流程

```
5 张迭代卡（9/21-9/25）
    ↓ 阿牛哥 + 大海 审
    ↓ 评估：每条"采纳/暂缓/驳回"
采纳：版本 v1 → v2.5 切换，更新白皮书 §7.8 / §7.10
暂缓：等更多数据，进 v3 候选池
驳回：记录理由，归档到"未采纳变更"
    ↓
9/29 起 9/30/10/6 三天用 v2.5 验证期
10/13 出月度 v3 路线图
```
