## 三、对齐机制 v2.0（可执行版）

### 3.1 数据契约

| 字段 | WB 侧 | 大海侧 | 对齐要求 |
|---|---|---|---|
| 文件路径 | `predictions/{date}.json` | `predictions-dahai/{date}_dahai.json` | 各自目录，互不覆盖 |
| 大盘方向 | `t1_prediction.sh_index.direction` | `market_overview.direction` | 必须可枚举比较（up/down/neutral） |
| 个股方向 | `stock_calls[].direction` | `predictions[].t1.direction` | 按 code 逐只比对 |
| 核心池 | `core_pool`（6只） | `core_pool`（6只） | 代码必须一致（已对齐） |
| 时间戳 | `data_basis.as_of` | `predict_date` | 标注数据基准时点 |
| 参数版本 | `_param_versions` | 需大海补 | 评分口径可追溯 |

**方向枚举统一**：`up` / `down` / `neutral`（避免"偏多/看涨/上行"混用）

### 3.2 决策规则（阿牛哥 9/28 重申）

```
双方方向一致 → 信号确认 → 报买点（仍受大盘门约束）
双方方向分歧 → 不出手 → 进评分仲裁
一方无数据   → 视为未对齐 → 不出手（当前状态）
```

**关键：分歧不是坏事，是评分机制的输入。但一方缺席时，不能假装对齐。**

### 3.3 评分仲裁（分歧时启用）

沿用白皮书 §7.10 的双模型权重：

| 维度 | 权重 | 来源 |
|---|---|---|
| 大海 v1.1-kuramoto 综合得分 | 40% | 大海侧 |
| WB 止跌信号（量比/MACD/RSI6） | 40% | WB 侧 |
| 阿牛哥人工确认 | 20% | 人工 |

**累计分歧样本**：3 次（WB 3:0）——样本太少，暂不调权重，继续攒到 ≥10 次

### 3.4 节奏（现实版，不画饼）

| 时点 | 动作 | 责任人 | 前提 |
|---|---|---|---|
| 11:30 | WB 生成预测 + 推送 | WB（需 token） | 会话触发 |
| 14:00 | WB 尾盘扫描 + 推送 | WB | 会话触发 |
| 14:10 | 大海拉取 + 逐只对齐 | 大海 | 大海侧调度 |
| 16:00 | WB 收盘版 + 推送 | WB | 会话触发 |
| 16:10 | 双方对账 + 写 reconciliation | 双方 | 数据齐备 |

**诚实标注：WB 侧当前依赖会话触发（沙箱会休眠），不是无人值守。**
替代方案：阿牛哥每天 11:30 前、14:00 前各叫一次 WB（各 1 分钟）。
