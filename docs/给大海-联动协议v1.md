```
predictions/
├── 2026-09-21.json            # 我方（WorkBuddy）主交付，含全部细节
```

**v1.0 → v1.1 变更**：删除 `wb-{date}.json` 镜像副本。WorkBuddy 直接以主名 `YYYY-MM-DD.json` 交付，reconcile.py 默认读主名 + `dahai-*.json`。

`reconcile.py` 默认从 `predictions/{date}.json`（WB）+ `predictions/dahai-{date}.json` + `predictions-dahai/{date}_dahai.json`（GH 兜底）读双方预测。

## 2. 双方字段约定

### 共同必须字段（任一缺失 reconcile.py 报 schema 错）
```json
{
  "code": "601899",                 // 6位代码
  "signal_date": "2026-09-21",      // 信号日
  "action": "watch_rebound",        // watch / buy / hold / sell
  "direction": "up",                // up / down / neutral
  "track_rule": "short_oversold"    // 短轨=short_oversold, 长轨=slow_bull_hold
}
```

### 我方额外提供（WorkBuddy 专有）
- `oversold_score_v15`（0-100，三口径融合分）
- `dd_30d`（30日高点回撤，负数）
- `rsi6`（RSI6 Wilder 周期）
- `signal_type`（oversold_rebound / slow_bull / watchlist）
- `core_pool`（true=核心池，false=26只观察池）
- 完整 `reason`（人话，包含数据引用）

### 大海侧建议提供（大海专有）
- `v12_6_score`（v12.6 评分 0-100）
- `r_value`（市场环境/板块共振 R 值）
- `oversold_threshold`（个股自定义反弹阈值，如京东方 10%）
- `rebound_days`（预测反弹天数）
- 你的 `reason`（包含 v12.6 视角的理由）

## 3. track_rule 取值

| track_rule | 仓位 | 止盈 | 止损 | 周期 | 适用 |
|---|---|---|---|---|---|
| `short_oversold` | 10% | +5% | -5% | 10日 | 4 只超跌股默认 |
| `slow_bull_hold` | 20% | 无 | -15% | 20日 | 半导体ETF/五粮液 |

不在核心池的 26 只观察股 track_rule 用 `short_oversold` 或 `watchlist`。

## 5. 对账引擎行为

```
predictions/{date}.json 缺失    → 仅跑 WorkBuddy 边，告警 "WB 文件缺失"
predictions/dahai-{date}.json 缺失 → 仅跑 DaHai 边，告警 "DaHai 文件缺失"
两边都有但字段冲突 → 告警 schema mismatch，但不阻断（v1.1 兼容期）
```

## 6. 异常处理

| 异常 | 处理 |
|---|---|
| 大海文件未在 09:30 前到达 | reconcile.py 自动跳过 Dahai 边，L2/L3 仅 WB |
| `v12_6_score` 大海未填 | 对账时该字段留空，不影响 L1 方向命中 |
| 数据基准日不一致 | 双方必须在 `signal_date` 和 data_basis 字段标清楚，reconcile 会告警 |
