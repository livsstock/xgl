## 二、洞 1（最致命）：你的 `label` 字段，脚本根本读不到

这是最要命的一条。

你的 9/21 数据里，大盘判断在这里：

```json
"market_environment": {
  "R_value": 0.52,
  "label": "偏多",          ← 实际值在这
  "based_on": "9 票池 Kuramoto 七因子共振分析"
}
```

但 `extract_market_direction()` 读的是：

```python
else:
    mo = data.get("market_outlook", {})    # ← 读的是 market_outlook
    if mo:
        direction = normalize_direction(mo.get("direction", ""))
```

**`market_outlook` 在 9/21 的大海数据里不存在。** 顶层 keys 是：

```
'_说明', 'predictor', 'schema_version', 'signal_date', 'predict_date',
'data_basis', 'core_pool_basis', 'market_environment', 'stock_calls', '_待填字段'
```

没有 `market_outlook`，也没有 `market_direction`。所以 `dh_dir = "unknown"`。

### 为什么这条特别危险

因为 `normalize_direction("偏多")` 是**能正确返回 `bullish`** 的（映射表里有"偏多"）。**你的归一化函数是对的，只是喂给它的字段是空的。**

换句话说：**你给核心股写了 `direction` 字段被正确读取（§你已修的方向分歧bug），但大盘的 `label` 没人读。** 同一个坑，在两个地方。

### 建议改法

```python
def extract_market_direction(data, source="wb"):
    if source == "wb":
        ...
    else:
        # 兼容多种字段位置
        for path in [
            lambda d: d.get("market_outlook", {}).get("direction"),
            lambda d: d.get("market_direction"),
            lambda d: d.get("market_environment", {}).get("label"),   # ← 加这条
            lambda d: d.get("market_environment", {}).get("direction"),
        ]:
            v = path(data)
            if v:
                return {"direction": normalize_direction(v), ...}
        return {"direction": "unknown", ...}
```

## 三、洞 2：门读的是"次日预测"，不是"当日状态"

WB 侧读到了 `bullish`，来源是：

```json
"t1_prediction": {
  "sh_index": {"direction": "up", "close_ref": 3911.87}
}
```

**⚠️ 但 `t1_prediction` 的意思是"T+1 预测"，不是"当前大盘状态"。**

这两个东西在当前场景下**方向可能完全相反**：
- 大盘正在走弱（当日状态 = 弱）
- 但模型判断"明天会反弹"（T+1 预测 = up）

于是风控门看到 `bullish`，判定"风向偏多，可正常买股"——**而实际上大盘状态是弱的**。

### 这是设计层面的问题

大盘风控门要回答的问题是：**"现在这个市场，该不该开仓？"**

那它应该读**当期状态**，不是**次日预测**。这两个混用，等于问"现在下雨吗"，然后拿"明天天气预报"回答。

### 建议：明确分离两个字段

| 字段 | 含义 | 用途 |
|------|------|------|
| `market_direction` | **当期大盘状态** | 🔒 风控门唯一输入 |
| `t1_prediction.sh_index.direction` | 次日预测 | 仅作参考展示 |

WB 侧我这边已经在 `predictions/*.json` 顶层加了 `market_direction` / `market_confidence`（9/29 起有值）。建议你那边也加。**如果字段缺失，风控门应当报 `BASIS_UNKNOWN`，而不是默认放行。**

## 四、洞 3：`unknown` 被当成"安全"

看你的判定逻辑：

```python
both_bearish = wb_dir == "bearish" and dh_dir == "bearish"
one_bearish  = wb_dir == "bearish" or  dh_dir == "bearish"
```

如果一方是 `unknown`：

- `both_bearish` = False（因为 unknown ≠ bearish）
- `one_bearish` = False（同上）
- → 落到 `else` → **NORMAL → 放行**

**"读不到方向"被判成了"安全"。** 这跟我在 `align_norm.py` 里踩过的坑一模一样，我当时的处理是加 `BASIS_UNKNOWN`，原则是：

> **宁可报"无法判断"，不报"安全"。**

风控门的失败模式必须是 **fail-closed（读不到就拦）**，不能是 fail-open（读不到就放）。

### 建议改法

```python
dirs_known = wb_dir in ("bullish","bearish","neutral") and dh_dir in ("bullish","bearish","neutral")

if not dirs_known:
    return True, "UNKNOWN", "⚪ 大盘方向读取失败 — 保守起见暂停开仓，请检查数据字段"
if both_bearish:
    return True, "CRITICAL", ...
```

## 五、我跑了复现验证 —— 结果比预想的更反直觉

我把三个洞分别补上，实际跑了一遍 9/21：

```

--- 场景B: 洞1未修（大海读不到） + 修洞3 fail-closed ---
判定: UNKNOWN  is_high_risk=True
→ ✅ 拦下
```

### 这里有个反直觉的结论，我必须说清楚

| 场景 | 判定 | 结果 |
|------|------|------|
| 现状（v2 实际） | `WB=bullish, DH=unknown` → NORMAL | ❌ 放行 |
| **只修洞 1**（补上字段读取） | `WB=bullish, DH=bullish` → **NORMAL** | ❌ **仍放行** |
| 洞 1 不修 + 修洞 3（fail-closed） | `DH=unknown` → **UNKNOWN** | ✅ **拦下** |

**注意第二行：把洞 1 修好，反而让 9/21 更"合理地"放行了。**

因为修好之后，大海的 `label="偏多"` 被正确读成 `bullish`，双方都是偏多 —— 门看到"两边都看多"，判定 NORMAL，**理直气壮地放行**。

而现在这个"读不到"的 bug，反倒误打误撞让洞 3 有机会把它当 unknown 拦下。

### 所以真正的优先级是反的

**先修洞 3，不要急着修洞 1。**

- 修洞 3（fail-closed）：**立刻**把 9/21 这类"读不到方向"的情况拦下，是纯收益
- 修洞 1（读 label）：单独修没有意义，甚至有害 —— 会让一个**错误的方向判断**（9/21 双方都判偏多）被正确地执行

**根子上不是字段读不到，是 9/21 双方对大盘的方向判断都错了。**

你自己也说了这话。但 v2 的架构还建立在"双方方向判断可信"这个前提上，而这个前提在 9/21 不成立。修洞 1 只是让错误的前提被更顺畅地执行。

### 那怎么才能真正拦住 9/21？

方向判断错了，靠"读对字段"救不回来。我认为至少要加一条**独立于方向判断的硬约束**，比如：

| 候选硬约束 | 说明 | 验证状态 |
|-----------|------|---------|
| 大盘跌破 MA20 一定幅度 | 不看模型判断，看客观价格 | 待回测 |
| 大盘 N 日累计跌幅超阈值 | 同上 | 待回测 |
| 双方方向一致且置信度都 > X | 一致性也可能是共同错误 | ⚠️ 9/21 就是共同错误 |

**注意第三行。** 9/21 双方方向一致（都偏多），一致性并没有帮上忙 —— 反而是一起错了。

所以**不要用"双方一致"当安全信号**。这是这次最重要的教训之一。
