## 三、推荐统一方案

### 3.1 方向枚举（最重要，先定这个）

**统一为 3 值**：`up` / `down` / `neutral`

| 来源 | 原值 | 归一 |
|---|---|---|
| 大海 v12.6 | `bearish` | `down` |
| 大海 v1.1 | `偏空` | `down` |
| 大海 v1.1 | `偏多` | `up` |
| 大海 v12.6 | `bullish` | `up` |
| WB | `up/down/neutral` | 原样 |

**理由**：英文无编码问题、无歧义、大小写容易规范；中文值在 JSON 传输和历史文件里出现过 3 种写法（偏多/偏空/平）。

**兼容策略**：双方**写入时只用 3 值**，**读取时用归一化函数兜底**。我已实现在 `align_norm.py::norm_direction()`，支持 20+ 种写法。

### 3.2 大盘方向字段路径

**推荐**：双方都加一个**顶层平铺字段**，避免深层嵌套

```json
{
  "market_direction": "down",        // ← 顶层，3值枚举，必有
  "market_confidence": 0.65           // ← 顶层，0-1 或 0-100 均可（标注在 units）
}
```

**保留各自原有结构**（不破坏现有解析），但**对账只读顶层这两个字段**。

- 大海：`market_outlook.direction` → 同时写 `market_direction`
- WB：`t1_prediction.sh_index.direction` → 同时写 `market_direction`

### 3.3 标的数组

| 项 | 统一建议 |
|---|---|
| 数组名 | `stock_calls`（双方 9/24 后已一致） |
| 代码 | **纯数字**，不带 `sh`/`sz` 前缀（`601899` 而非 `sh601899`） |
| 名称 | `name` |
| 方向 | `direction`：`up/down/neutral` |
| 动作 | `action`：`buy/sell/hold/watch` |
| 理由 | `reason`：自由文本 |

**代码前缀问题**：大海用 `sh601899`，WB 用 `601899`。建议统一为**纯数字**，因为：
- 6 开头=沪市，0/3 开头=深市，规则明确
- 对账时不用做前缀剥离

**若不便改**，我的 `align_norm.py` 已做剥离（`"".join(ch for ch in code if ch.isdigit())`），不影响对账。
