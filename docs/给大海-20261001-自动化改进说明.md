# 自动化流水线改进说明（2026-10-01）

## 改动背景

WorkBuddy 在 9/30 的交叉验证中发现以下自动化缺陷：
1. **缺少 16:10 对账 workflow**：只有 8:00 采集，没有收盘后自动对账
2. **无交易日闸门**：9/25 中秋休市仍生成预测文件，产生空壳数据
3. **日历不统一**：`align_core6.py` 和 `daily_collect.py` 各自维护节假日表，易不一致
4. **无降级告警**：预测管道降级时没有自动告警机制
5. **空壳文件未清理**：`predictions-dahai/2026-10-01_dahai.json` 是空壳

## 本次改动

### 1. 新增 `scripts/trade_calendar.py` — 单一日历源
- 所有交易日判断统一引用此模块
- 包含 2026 年完整节假日表（依据国务院办公厅通知）
- 提供 `is_trading_day()`, `beijing_today()`, `shift()`, `next_trading_day()`, `prev_trading_day()` 等函数
- 内置自检：运行 `python scripts/trade_calendar.py --selftest` 验证

### 2. 修改 `daily_collect.py` — 加入交易日闸门
- 开头增加交易日检查：非交易日自动跳过，不执行采集
- `get_trade_date()` 改为调用共享交易日历，支持节假日
- 版本号升至 v2.2

### 3. 新增 `.github/workflows/daily-reconcile.yml` — 16:10 对账
- 每工作日北京时间 16:10 触发
- 先检查是否交易日，非交易日自动跳过
- 运行 `scripts/align_core6.py` 执行双模型对账
- 检查预测文件质量（空预测/版本回退/null 数据）
- 结果自动 commit & push

### 4. 修改 `.github/workflows/daily-collect.yml` — 加入交易日闸门
- 在采集前增加交易日检查步骤
- 非交易日跳过整个采集流程
- 指定 `ref: main` 确保使用最新代码

### 5. 修改 `anomaly_detector.py` — 新增预测管道降级检测
- 新增 `check_prediction_quality()` 函数
- 检测：predictions 为空、模型版本回退、close 为 null
- 降级信息写入 manifest.json 和 anomaly_alert.md

### 6. 修改 `scripts/align_core6.py` — 引用共享日历
- 移除本地硬编码的 CN_HOLIDAYS_2026 和 is_trading_day 等函数
- 改为 `from trade_calendar import ...` 统一引用
- 修复跨长假（如国庆）的交易日计算

### 7. 删除 `predictions-dahai/2026-10-01_dahai.json`
- 该文件为空壳（predictions: [], close: null, 模型退回 v1.1）

## 验收方法

```bash
# 1. 确认交易日闸门正常（今天 10/1 是休市日）
python -c "
import sys, os
sys.path.insert(0, 'scripts')
from trade_calendar import beijing_today, is_trading_day, describe
today = beijing_today()
print(f'today = {today}')
print(f'is_trading_day = {is_trading_day(today)}')
print(f'describe = {describe(today)}')
"
# 预期：is_trading_day = False, describe = 节假日休市(国庆)

# 2. 确认下一个交易日是 10/9
python -c "
import sys; sys.path.insert(0, 'scripts')
from trade_calendar import next_trading_day
print(next_trading_day('2026-10-01'))
"
# 预期：2026-10-09

# 3. 运行交易日历自检
python scripts/trade_calendar.py --selftest
# 预期：全部通过 ✅
```
