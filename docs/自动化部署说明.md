## 文件清单

| 文件 | 用途 |
|---|---|
| `daily_predict.py` | 核心预测生成器，单次执行产出 `predictions/{date}.json` |
| `cron_runner.py` | cron 守护包装：时点判定 + 周末跳过 + 失败重试 |
| `logs/daily_predict-{date}.log` | 运行日志（每次跑都追加） |
| `logs/cron.log` | cron 自身日志 |

## 三个 cron 时点（建议）

A 股交易时段是 9:30-11:30 + 13:00-15:00。挑三个有意义的时点：

| 时点 | 用途 |
|---|---|
| **11:30** | 上午盘收盘后，捕捉上午定性 |
| **14:00** | 尾盘买入决策（与 `afternoon_scan.py` 时点对齐） |
| **16:00** | 收盘后定格，覆盖全天 |

```bash
crontab -e
# 添加以下三行：
30 11 * * 1-5 cd /workspace/finance_task && python3 cron_runner.py >> logs/cron.log 2>&1
0  14 * * 1-5 cd /workspace/finance_task && python3 cron_runner.py >> logs/cron.log 2>&1
0  16 * * 1-5 cd /workspace/finance_task && python3 cron_runner.py >> logs/cron.log 2>&1
```

## 手动触发

```bash
# 跑今天的预测
python3 /workspace/finance_task/daily_predict.py

# 补跑某天（用于回填历史）
python3 /workspace/finance_task/daily_predict.py --date 2026-09-23

# 生成时点快照（如 14:00 时点）
python3 /workspace/finance_task/daily_predict.py --config
```

## 退出码

| 退出码 | 含义 | cron 会如何感知 |
|---|---|---|
| 0 | 26 只全覆盖，无失败 | 静默成功 |
| 1 | 大盘数据全挂（M_sse 兜底 50） | 数据异常 |
| 2 | 失败 ≥10 只 | 数据严重缺失，需人工介入 |

cron 默认不邮件告警，建议接入 wecomcli 飞书通知（下一步 v1.1）

## 已知 v1.0 限制

1. **节假日过滤**只做了周末跳过，A 股法定节假日未接入（十一/春节会跑空，浪费 cron 配额）
2. **资金流向数据未接入**（你点出的板块轮动盲区，v1.1 解决）
3. **GitHub push 未接入**（认证问题，需要 PAT 之后才能补 push 步骤）
4. **失败邮件/微信通知未接入**（cron 失败只能等下次人工看 log）
